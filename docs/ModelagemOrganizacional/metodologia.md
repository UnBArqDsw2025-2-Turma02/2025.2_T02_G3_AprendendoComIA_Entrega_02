## Técnica Utilizada

A modelagem organizacional foca em definir o escopo, a estrutura e os requisitos do sistema a partir de uma perspectiva de alto nível, alinhada às necessidades do negócio e dos usuários. Para o projeto "Aprendendo com IA", utilizamos dois diagramas UML que se complementam:

1.  **[Diagrama de Caso de Uso](ModelagemOrganizacional/diagramaDeCasoDeUso.md):** Utilizado para capturar os requisitos funcionais do sistema sob a ótica do usuário (ator). Ele descreve as interações entre os atores e o sistema para alcançar objetivos específicos, respondendo à pergunta: "O que o sistema deve fazer?". É a principal ferramenta para definir o escopo e as funcionalidades que agregam valor ao usuário.

2.  **[Diagrama de Pacotes](ModelagemOrganizacional/diagramaDePacotes.md):** Empregado para organizar os elementos do modelo em grupos lógicos (pacotes), mostrando a estrutura modular do sistema e as dependências entre esses grupos. Ele responde à pergunta: "Como o sistema está organizado?". Este diagrama ajuda a gerenciar a complexidade, promovendo uma arquitetura mais coesa e de baixo acoplamento.

A combinação desses artefatos cria uma ponte entre a visão do usuário (o que ele quer fazer) и a organização interna do software (como as funcionalidades são agrupadas), estabelecendo uma base sólida para as modelagens estática e dinâmica.

## Objetivos

O principal objetivo da modelagem organizacional é estabelecer uma compreensão clara e compartilhada sobre o propósito e a estrutura do sistema "Aprendendo com IA". Os objetivos específicos são:

- **Definir o Escopo do Sistema:** Utilizar os casos de uso para delimitar claramente as funcionalidades que serão desenvolvidas, garantindo que o projeto atenda às expectativas dos stakeholders.
- **Estruturar a Arquitetura em Alto Nível:** Organizar o sistema em módulos lógicos e coesos por meio do diagrama de pacotes, facilitando a distribuição de tarefas e a manutenção futura.
- **Facilitar a Comunicação:** Criar uma linguagem visual comum que permita que tanto a equipe técnica quanto as partes interessadas (não técnicas) entendam o comportamento e a organização do sistema.
- **Guiar as Fases Seguintes:** Servir como um ponto de partida e um guia para a criação dos diagramas de modelagem estática (classes, componentes) e dinâmica (sequência, atividades), garantindo que eles estejam alinhados aos requisitos funcionais e à estrutura modular definida.
